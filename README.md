一个本地离线单机游戏库管理器。把散落在硬盘上的游戏文件夹扫成一张樱花色的桌面：
双击启动、单击看体积构成、右键管理，起不来的时候告诉你为什么。

面向的是**没有统一元数据的库** —— 目录名与可执行文件名毫无关系、一个文件夹里躺着十几个 exe、
没有商店 ID 也没有统一命名。所以这里绝大部分判断都从文件本身来：哪个 exe 是游戏、
用的什么引擎、为什么起不来、要不要转区，全是读出来的，不是查出来的。

只有一件事读不出来 —— 这游戏讲的是什么。那要问目录站，而那一步默认关着。

## 一眼看完

- 扫文件夹，自己挑出主程序；十几个 exe 里挑不动的，右键换，每一个都写明凭什么这样判定
- 起不来的时候读 PE 导入表，指名道姓地说缺哪个运行库；引擎弹的日文乱码报错框，还原成日文原文
- 题材标签（校园 / 催泪 / NTR…）从目录站取，**默认关闭**，开着的时候也只发标题
- 游玩时长按「游戏目录里还有没有进程」算，扛得住启动器自己退出的那类游戏
- 800×600 的老游戏可以实时超分放大到满屏（**默认关闭**），启动游戏时自己起、关掉游戏自己退；
  放大器可以选 Magpie（随包分发）或 Lossless Scaling（你自己在 Steam 上买的那份）
- 存档备份会去 `%APPDATA%`、`LocalLow`、C 盘根目录这些地方找 —— 存档常常不在游戏目录里；
  下载包自带的通关存档也会被认出来
- 分享打包会先列出个人痕迹让你过目，**原文件夹分毫不动**
- 卸载要三步：确认 → 手抄花名 → 长按 2.5 秒

## 功能

### 扫描与识别

- **自动扫描** — 指定若干文件夹，自动识别其中的游戏并挑出主程序。能应付嵌套深度不一、
  目录名与可执行文件名毫无关系、以及混在一起的安装包残留
- **找出真正的启动器** — 一个文件夹里十几个 exe，谁都分不清哪个是游戏。右键「更换主程序…」
  会把它们分成 推荐 / 区域模拟器 / 工具·补丁·卸载 / 子目录 四类，并写明每一个是**凭什么**
  这样判定的（文件名特征、体积、版本信息）。拿不准就**试运行** —— 启动器会去看游戏目录里
  有没有进程真的跑起来，把「点了没反应？」变成一个有答案的问题
- **认得出引擎** — KiriKiri / BGI / Siglus / Majiro / NScripter / Artemis /
  Ren'Py / RPG Maker / Wolf / Unity / Unreal / TyranoScript / NW.js。
  引擎决定了崩溃日志写在哪、要不要区域模拟器，诊断的准头大半来自这里
- **原生图标** — 直接解析可执行文件的 PE 资源，取出内嵌的最大尺寸图标（通常是 256×256），
  大磁贴也清晰；只有小图标的游戏改用生成的占位磁贴，而不是把 48px 拉糊

### 起不来的时候

- **读得懂引擎自己的报错** — 游戏起不来时，引擎往往会弹一个消息框说明原因，而那句话通常
  没人看得懂：日文引擎写的是 Shift-JIS，在中文系统上会显示成 `巜掕偝傟偨僼傽僀儖` 这种
  乱码。诊断会直接把窗口里的文字读出来并还原成日文原文，两者都摆给你看。
  这是整个诊断里唯一不靠推断的一条 —— 别的都在猜，只有它是引擎自己说的
- **启动诊断** — 双击之后十几秒没有任何进程，不再是一片沉默。它会去读主程序的
  PE 导入表，按 Windows 的搜索顺序逐个解析，缺哪个运行库就指名道姓地说
  （VC++ 哪一年、DirectX 末端运行库、N 版系统缺的 Media Feature Pack）；
  读内嵌 manifest 判断是不是要管理员权限，并直接提供提权启动；
  发现选中的其实是卸载程序或设置工具就说出来；按引擎与文件名判断要不要区域模拟器；
  进程起来过又秒退的，去找游戏刚写的那份日志并把末尾贴出来。
  查不出问题时会列出**查过哪些项**，而不是给一句「一切正常」。
  全部本地判定，不联网，也不写游戏文件夹
- **组合启动** — 日文游戏常要经区域模拟器才能正常显示。可以直接设成
  「用 `NTLEA.exe` 启动 `游戏本体.exe`」，双击磁贴时就是这一串

### 放大到满屏（默认关闭）

这些游戏的分辨率大多被引擎焊死在 800×600 或 1024×768，在今天的屏幕上是邮票大的一块，
交给系统拉伸又会糊成一片。开启后，启动游戏时会顺带把放大器拉起来，把游戏窗口实时放大到屏幕
大小 —— 它按主程序路径自动匹配，不用手动对准窗口，游戏关掉一两分钟后自己退出。

**放大器有两个可选，只能选一个**（两个抢同一个窗口没有意义）。不管选哪个，
「哪些游戏放大、用哪种模式」都是同一套设置：设置里选一个默认模式，单个游戏在右键菜单里另选，
选择写进 `sakura-launcher.md` 跟着文件夹走。

#### Magpie（随包分发）

预置七种缩放模式：Lanczos、FSR、FSRCNNX、CuNNy、Anime4K、CRT-Geom、Integer Scale 2x。
Lanczos 最省、什么显卡都跑得动；Anime4K 对动画风格的立绘最好看，也最吃显卡。

更细的画质设置 —— 着色器自身的参数、捕获方式、帧率限制、光标缩放 —— 在 Magpie 自己的界面里，
设置页的「画质设置…」是它的入口。那里还能用 `effects\` 目录下的一百多个着色器**新建自己的缩放模式**，
新建好的模式会直接出现在本程序的下拉框和右键菜单里：这两处列的就是 Magpie 配置里现有的模式，
而不是写死的七个。在 Magpie 里改的东西本程序不覆盖（只有自动更新检查、托盘图标、提权和调试开关
是强制的）。注意 Magpie 是退出时才保存配置的，所以调完请从托盘正常退出它，再去启动游戏。

需要 Windows 10 1903 以上、支持 DirectX 11 的显卡。以管理员身份启动的游戏要在设置里额外允许
Magpie 也提权（更省事的办法是以管理员身份运行本启动器）。随时可以按 Alt+Shift+A 手动放大当前窗口。

#### Lossless Scaling（需自行购买安装）

[Lossless Scaling](https://store.steampowered.com/app/993090/) 是 Steam 上的付费第三方软件，
**本程序不分发、不代下、也不会替你安装它** —— 只是在它已经装好时驱动它。它除了放大还能插帧（LSFG）。

它的位置从 Steam 的库记录里自动找。找不着也不要紧：设置里有「手动选择 LosslessScaling.exe…」，
**这个按钮一直在**，因为 Steam 装在别处、库文件夹搬过、目录被整个拷走、注册表被清理过都会让自动
查找落空或者找错；手动指定优先于自动查找，旁边有「回到自动查找」可以撤销。

**五档预设，开箱即用。** 前三档是画质阶梯 —— 性能优先（锐化双三次，基本不吃显卡）、画质优先、
极致画质（后两档用 Anime4K，专为手绘动画画面做的，最后一档最重也最好看）。

后两档解决的是另一个问题：**放大倍率往往不是整数**。800×600 的游戏放到 1440p 屏上是 2.4 倍，
于是有的线占两像素、旁边的占三像素 —— 不糊也不歪，就是粗细看着不均，而 Anime4K 因为先锐化再重采样，
反而会把它放大。「线条均匀」先按整数倍放大再补余数，粗细一致且照样铺满屏幕；「整数倍放大」干脆
只用整数倍，五档里最锐，代价是四周留黑边。

五档都**保持 4:3 比例**（不然 800×600 拉成 16:9，脸会变宽），并且**都关掉插帧** ——
插帧是给动作游戏的，文字冒险游戏画面本来就是静止的，只会白白增加延迟和伪影。

预设**也是克隆**，不是凭空造的一条：它复制你的默认配置，只覆盖上面那几项，显卡选择、鼠标灵敏度、
光标是否限制在窗口内这些照你在 Lossless Scaling 里设的来 —— **捕获那一组是例外**。五档预设都用 **WGC**，理由是鼠标：DXGI 抓的桌面图像里不含光标，LS 只能自己画一个，而它只在拿到新画面时才画；文字冒险游戏画面是静止的，指针就卡住不动了。WGC 让系统把光标合成进捕获帧，指针自然跟手。WGC 需要 Win11 24H2 以上，旧系统 LS 会自动退回 DXGI。跟着一起改的还有两项：**关掉 G-Sync 支持**、**捕获队列设为 0**。只看发光卡的话这两项没道理，配上 WGC 才对：静止画面几乎不出帧，可变刷新率跟着这个帧率走就会把屏幕压到刷新率下限，而 LS 自己的说明里写着「显示硬件光标时，WGC 需要 MPO 支持才能让 VRR 正常运作」—— 两件事撞在一起，刚刚才看得见的指针就会一闪一闪地卡。队列同理：它把 1 和 2 留给「帧率无上限或不稳定、GPU 高负载」的场景，把 0 写成「始终使用最后捕获的帧」；一秒才填一次的队列不是缓冲，是延迟。它写进去的每一个值都是从 LS 程序集元数据里读出来的
真实枚举成员 —— 不是照着界面上的字猜的（界面写 `Vsync3`，枚举成员其实叫 `VSYNC3`）。这不是讲究：
配置文件是 .NET 的 XmlSerializer 读的，遇到不认识的枚举值会直接抛异常，**整个文件都读不进去**，
代价是你在 LS 里的全部设置，而不是一个着色器选错。

**它会读一下你的显示器。** 只读、只在本机、不联网：型号、分辨率、刷新率、色深，以及 **HDR 是不是开着**。
这一项不是口味问题 —— 桌面开了 HDR，放大程序抓到的画面就是 HDR 格式的，跟游戏本身是不是 HDR 无关，
而配置里那个 HDR 开关要是关着，同一张画面就会被当成 SDR 处理，颜色直接不对，并且**不会报任何错**。
所以预设里的这一项由本程序按屏幕状态写；量不到就一个字都不写（不会替你猜成「关」），也留了手动挡。
**你自己建的配置一个字段都不改**，包括这一项 —— 那是你的设置，不一致只会在设置页里指出来。

显示器信息还用来把倍率算术用**你这台机器的真实数字**算给你看，而不是举个别人的例子。「整数倍」那一档
在窗口除不尽时会悄悄按 1.00 倍输出，游戏跑起来后本程序会量一次窗口客户区，真放不下就直接把数字报出来。

**配置写不进去时会一直提示。** Lossless Scaling 退出时按内存把整个配置文件覆写一遍，所以它开着的时候
本程序一个字都不写（停掉你自己买的软件来改它的配置，不是本程序该做的事）。这种「还没写进去」的状态会
常驻在设置页里，而不是弹个几秒就没的提示 —— 否则你改完基准配置以为生效了，实际上一直没生效。

不想用预设也行：下拉框里同时列着**你自己在 Lossless Scaling 里建的游戏配置**，选中哪条就整份复制
哪条，画质、插帧倍率、捕获方式、GPU 选择全部照你设的来 —— 本程序一个画质字段都不理解，
也就不会替你决定任何一项。

写进它配置文件的规矩有三条：只增删以「Sakura · 」开头的那几条，**你自己建的配置一条也不动**；
第一次写入前先把原文件备份到 `%APPDATA%\sakura-launcher\lossless\`；**它运行时一个字都不写** ——
它退出时会按内存把整个配置文件写回去，这时候改了也会被吞掉，所以本程序会提示你先退出它。
关掉这个后端时，我们加的那几条会被删干净。如果设置里选的模式在它那边不存在，
**本程序不会凭空建一条**，只会告诉你没有这个配置。

它要不要以管理员身份启动是它自己的设置，本程序只读不改；设成了就会在启动游戏时弹一次 UAC，
那样起来的一份本程序也关不掉，要自己从托盘退出。

#### 两边都一样的前提

游戏得是窗口化或无边框，独占全屏放大不了。如果游戏启动后转交给另一个可执行文件，按路径的自动匹配
会落空 —— 用「更换主程序…」指对即可，这同时也修好时长统计。放大不成从不影响游戏本身运行。

### 题材标签（唯一联网的功能，默认关闭）

校园、催泪、NTR 这类标签**不在游戏文件里** —— 那是对故事的判断，只有目录站有。

- **怎么找到这部游戏** — 文件夹名里带 RJ 号的走 DLsite 精确匹配，一个编号只对应一部作品，
  直接采用；其余的拿标题去 VNDB 搜。**中文名一样搜得到** —— VNDB 每部作品都存着各语言的
  标题，`示例游戏` 就是其中一条。搜不到时会**先问 Bangumi 这游戏的日文原名叫什么**，
  再拿日文名回头查一次 —— 日文名是从目录站的记录里查出来的，**不是猜的，也不是机翻**。
  几个结果都像的会列出来让你定，因为同名的续作和 FD 太容易搞混
- **名字乱也能对上** — 文件夹名很少是干净的标题。方括号、圆括号、全角括号里的汉化组和
  「官中」会剥掉，括号外的「官方中文版」「无修正」「硬盘版」也会；粘在标题上的版本号
  （形如 `样例游戏2v1.1.0`、`另一个游戏7.6.9`，形态取自真实文件夹名，标题换成了占位）、
  下划线、语言后缀、`.7z` / `.part1.rar` 一并处理，
  但**标题本身的数字留着**（`A.B.C.5` 不会被削成 `A.B.C.`）。
  清洗完还搜不到就退一步只搜开头一段 —— 目录站的搜索是子串匹配，
  多一个词会一无所获，少几个字反而找得到
- **实在对不上的自己搜** — `123456` 这种名字谁也猜不出来。确认对话框里每个游戏都带搜索框：
  日文名、中文名、英文名都行，也可以直接填 `v1234`、`RJ01234567` 或网址。
  右键任意游戏「手动匹配…」随时能打开
- **标签怎么显示** — DLsite 的分类跟着界面语言走；VNDB 的标签是英文，常见的一两百个有中文
  对照，表里没有的照原样显示英文，不瞎译。每个标签都写明**凭什么这么打**，悬停可见；
  判错了点一下划掉，随时能恢复
- **按标签筛选** — 顶栏下方是标签条，带数量，点击即筛。多个题材之间是「且」——
  再点一个是进一步收窄；**年份只能选一个**，毕竟一部作品不会既是 2016 年又是 2017 年，
  两个一起选只会得到一片空白
- **封面也从同一条记录取** — 目录站里封面、标签、简介挂在同一条作品记录上，所以查一次全都有了。
  **就一个入口**：右键单个游戏「联网获取资料」，或者**多选之后右键批量**，标签封面简介一起回来 ——
  分成两个按钮就是为一份答案跑两趟，还会落下一半没取。
  **只手动触发**，扫描、刷新、启动都不会联网。
  设置里可以单独关掉图片下载，只留标签
- **磁贴上已经有封面的，一律先问你** — 只要那个游戏已经有封面，目录站又拿回来一张，
  两张都留着，跑完之后弹一个窗口把它们**并排放在一起**让你挑。
  **不管原来那张是哪来的** —— 自己设的也好、上次查资料抓的也好。图片的出身说明不了
  你更想看哪张：一张你已经看了很久，另一张是刚下载的陌生人。
  在你点之前磁盘上什么都没变：目录站那张只是下载到程序自己的数据目录里等着，
  选「保留这张」或者直接关掉窗口，它就被删掉，库跟没查过一样。
  **两张一模一样时不会问**（逐字节比对）—— 那是同一个游戏查第二遍的正常结果。
  以前这里是两条都不对的规矩 —— 批量时闷头跳过，单个查时闷头替换 —— 两次都是在**没人看过
  这两张图**的情况下替你做了决定。手动匹配作品（那个搜索框）采用结果时走的也是这条路。
  R18 的那张在这里同样打码，跟磁贴上一个规矩
- **查错了可以整个撤销** — 目录站认错了作品、而网上又没有正确的条目可以改过来的时候，
  右键「**清除获取的资料**」把这次查询的结果整个拿掉：题材标签、简介、作品信息，
  以及目录站给的那张封面。**只拿掉目录站给的东西** —— 你自己打的标签、改的名字、
  评分、时长、以及你自己设的封面，一样都不动。
  清完之后这个游戏**不会再被「整库获取」自动查一遍**（否则下次一跑就把同一份错的又抓回来），
  想重试就单独右键那一个。多选之后也能一次清掉一批
- **顺带把这作品是什么记下来** — 同一条记录上还有**日文原名、中文名、发售日期、品牌/社团**，
  一并存下来，显示在游戏详情的「作品资料」里，作品编号点一下用浏览器打开目录站的条目页。
  这几样不是装饰：**改过名的游戏之所以还能用日文原名搜到，就是因为它们被记了下来** ——
  查一次的时候顺手取的，不查就永远不知道。
  **不取目录站的评分** —— 这软件里的评分是你自己打的星级，两套评分摆在一起只会互相打架
- **简介跟着封面一起回来** — 取封面的时候顺手把目录站的简介也带回来，显示在**游戏详情最下面**，
  并写明是谁写的。**没有单独的「获取简介」按钮** —— 图和字在同一条作品记录上，
  分两次要就是为一个答案跑两趟，所以开不开只在设置里一处决定。
  编号能直接对上的用 DLsite 自己的简介（那不用匹配，也就无从匹配错）；
  其余去 Bangumi 查一次，**只认名字对得上的那一条**，
  对不上宁可没有 —— 简介写错比没有更糟，因为它读起来跟真的一模一样
- **没有中文简介就翻一份，并且标明是机翻** — 目录站上不少作品只有日文简介
  （Bangumi 上很多条目直接抄了日文商店文案）。一概不要的话，大半个库都是空的，
  所以现在会机翻成中文 —— 但**一定标着「机翻」**，详情页和游戏文件夹里的说明文件都标。
  机器写的句子和人写的句子读起来一样，值的钱不一样，这一点不能含糊。
  翻译走 `translate.googleapis.com`，不通就退到 `api.mymemory.translated.net`；
  **要么整段翻完，要么当没有** —— 半段日文半段中文看着像游戏自己的简介出了问题。
  设置里可以单独关掉，关掉就回到「只要现成的中文」
- **发出去的只有标题** — 开启后，获取标签时发出去的只有两样东西：**文件夹名里的作品编号**，
  或者**游戏标题**。收方是 DLsite、VNDB、Bangumi 三个站。路径、体积、时长、评分、你的库有
  多大，一概不发，也没有任何标识你或这台机器的东西。
  **取封面会多一步**：向图片主机（`t.vndb.org`、`img.dlsite.jp`）请求那个图片文件本身。
  **翻译简介又多一步**：把目录站那段简介发给翻译服务
  （`translate.googleapis.com`，不通退到 `api.mymemory.translated.net`）——
  这两步各自一个开关，也正是因为它们发出去的东西比一个标题多。关闭时一个字节也不出去，
  **整个过程不碰游戏文件夹，只读文件夹的名字**
- **不想看的默认就不显示** — VNDB 标了剧透的标签**默认藏起来**，没人想在自己的书架上被剧透；
  **R18 标签同样默认不显示**，设置里有开关。标签照样取回来存着，开关只管画不画，
  随手一开一关立刻生效，不用重新联网。
  **R18 封面同样默认打码**（角上标一个 R18，免得你以为是图糊了）——
  尺度是目录站自己标的：VNDB 逐图有评级，DLsite 是整部作品的分级
- 只查没查过的，查过一次就不再重复问；随时可以停，也可以整库重查

### 记录与整理

- **游玩时长** — 不盯着自己启动的那个进程（大量游戏的启动器起完真正的程序就退出，
  那样每局都会被记成两秒），而是看**游戏目录里还有没有进程在跑**。
  能扛住自我重启、中途开配置工具、多进程引擎。
  代价是一个盲点：卡在报错框上的游戏也是「目录里有进程」。所以启动后会看一眼屏幕上
  到底是什么 —— 是报错框就不计时，并且告诉你它弹了什么
- **四个清单** — 全部 / 想玩 / 在玩 / 玩过。「在玩」和「玩过」可以同时成立
  （通关后开二周目），但「想玩」意味着还没开始，与前两者互斥。
  「想玩」清单只作规划，不能从那里启动
- **评分与评价是两套** — 星级评分在右键菜单里，任何页面都能打；tier 评价在它自己的页面上
  拖拽排位，因为 tier 的意义在于和别的游戏比。两者互不干扰，磁贴上显示的是星级
- **分组** — 右键空白处新建分组，把磁贴拖进拖出。拖到磁贴**左右两侧**会出现插入线、
  把它放到两个磁贴之间；拖到磁贴**正中间**才合并成一个分组。
  分组磁贴画成文件夹的样子，**双击打开**。分组只影响启动器里的排列，
  **不会移动磁盘上的任何文件**
- **文件夹自己也能拖，也能改名** — 按住文件夹磁贴拖动就能调整文件夹之间的先后，
  其余磁贴纹丝不动 —— 挪的是书架，不是书架上的东西。改名在文件夹的右键菜单里，
  打开文件夹之后标题栏上也有一个，因为想改名往往正是在看着里面装了什么的时候。
  「待安装」那个内置文件夹能拖，但不能改名也不能解散
- **排序** — 手动 / 名称 / 体积 / 安装·修改时间 / 最近启动 / 游玩时长，顶栏可直接切换。
  手动排序下拖拽即可自由调整位置
- **搜索认得出别名** — 顶栏搜索框除了磁贴上的名字，还认**日文原名、中文名、品牌**
  （查过资料的话）、**文件夹名**、以及你自己打的标签和题材标签。
  于是一个显示成中文、装在 `RJ01234567` 文件夹里的游戏，三种叫法都能把它找出来。
  文件夹的**上级目录不参与匹配** —— 那是每个游戏都有的，一搜就是整个库
- **重命名不动文件** — 右键重命名，新名字写进游戏文件夹里的 `sakura-launcher.md`。
  **不改文件夹名**，因为很多游戏按路径找资源，改名会让它们打不开。
  那个文件是带注释的 Markdown，直接编辑即可改名，删掉就恢复成文件夹名
- **说明文件随文件夹走** — 评分、时长、标签、主程序选择都写在游戏文件夹里的
  `sakura-launcher.md`，路径存的是相对路径。换硬盘、重装系统，库跟着文件夹一起走。
  手改过的文件会在你点顶栏「刷新」时读回来（比对修改时间，更新的一方胜出）；
  启动时的那次自动同步不做这件事，那要每个游戏一次磁盘往返
- **联网查回来的东西也一起写进去** — 作品编号、原名、中文名、发售日期、品牌、
  题材标签、简介、封面文件名，都记在同一个 `sakura-launcher.md` 里；**封面本身也存进游戏文件夹**，叫 `sakura-cover.jpg`。
  于是你改了显示名、查过标签之后，**换个版本、换台机器、把文件夹改成
  `游戏 v2.3 完整版【全CG存档】`，这些东西一样在** —— 重新扫进来就全回来了，一次网都不用联。
  这里的关键是**记文件名而不是记路径**：路径是「这台机器上的事实」，文件夹一改名就不再成立；
  文件名是相对说明文件自己的位置去找的，所以文件夹叫什么、在哪个盘、是不是别人发给你的，都不影响。
  就算说明文件里那行封面被你删了，扫描还会去文件夹里找 `sakura-cover.*` —— 两条路，断一条还有一条。
  R18 标签和剧透标签在文件里**分行写**，不是为了好看：混成一行读回来，
  这两类标签就会直接出现在书架上
- **哪些不写进去** — 「哪个游戏放在哪个分组」「磁贴的排列顺序」这些是**你这台机器上的桌面布局**，
  不是这个游戏的属性，跟着文件夹走没有意义，所以只留在本机
- **刷新 ≠ 重新扫描** — 顶栏的「刷新」只同步已有条目（名称、体积、说明文件、是否还在原处），
  从不擅自加新东西。往文件夹里新放了游戏，去设置里对那个目录点「重新扫描并添加」，
  会像添加文件夹一样列出可添加的内容让你勾选
- **移除磁贴** — 右键「从库中移除」把误扫进来的非游戏内容拿掉，**不删除任何文件**；
  路径会被记住，重新扫描不会再加回来。设置里可以单个或全部恢复 ——
  恢复时封面、评分、时长、标签都会一并回来

### 空间与收发

- **体积构成** — 单击磁贴滑出详情，环形图有两种模式：占游戏库多少，
  以及游戏文件夹内部各项占多少，可逐层下钻
- **磁盘页** — 各盘容量、体积 Top 10，以及「冗余安装包」清单：
  已确认存在解压副本的压缩包，勾选后批量移入回收站
- **下载** — 把链接交给 IDM / aria2c / 系统默认程序 / 自定义命令行，下完的压缩包
  自动进入「待安装」。`X.7z.001`、`X.part2.rar` 这样的**分卷**是一套，照常自动解压；
  但如果下回来的是**几套互不相关的压缩包**（本体一个、补丁附件各一个的常见发布方式），
  程序不解压，只在右下角弹一张卡片列出每一套，等你自己去文件夹里挑。
  哪个是本体、哪些是补丁，得打开才知道，猜错就是一个装了一半的库。
  这张卡片按按钮才消失，不会自己淡掉
- **待安装** — 库里的压缩包条目。右键「一键解压」装上，双击会提醒它还没装
- **存档备份** — 右键「备份存档…」，把存档复制到你指定的目录（默认「文档\Sakura Launcher Saves」），
  多选可以一次备份多个。每次备份是一个带时间戳的新文件夹，**从不覆盖上一次**。
  **只复制，游戏文件夹一个字节都不改。**
  存档常常**不在游戏目录里** —— Ren'Py 的权威副本在 `%APPDATA%\RenPy`，Unity 在 `LocalLow`，
  RPG Maker MV 这类 NW.js 游戏藏在 `%LOCALAPPDATA%` 的 leveldb 里，还有把存档写到 C 盘根目录的。
  所以这里会按引擎去这几个地方找目录名对得上的文件夹。
  找到的东西分两栏：**游戏目录里的、以及这个引擎该写的地方**，默认勾上；
  **只是名字对得上、但引擎不该写那儿的**，列出来写明理由，**默认不勾** —— 名字撞车是常事，
  得你自己认。找漏了随时「添加文件夹…」自己指，指过一次就记住了。
  另外，这类游戏下载包里**常常自带一份通关存档**，和你自己的存档在文件名、扩展名、
  所在目录上完全一样。唯一能区分的是时间：**加入库之后从没写过的，会标出来并默认不勾**
  （2026 年 8 月之前就在库里的条目没有这个基线，界面上会直说分不出来）。
  **没有「还原」按钮，这是故意的** —— 还原要覆盖你现在的存档，是这个程序里唯一能弄丢东西的操作。
  每个备份里会写一份 `sakura-backup.md` 记着每样东西原本在哪，要放回去请自己复制
- **分享** — 右键「分享…」把游戏打包发给别人。会先扫出个人痕迹（存档、日志、截图，
  以及启动器自己那份记着游玩时长和评分的说明文件），**列出来让你过目再决定排除哪些**。
  可选 7z / zip、加密码（7z 还能连文件名一起加密）、自定存放位置。
  多选时每个游戏各压一个包，按顺序逐个进行。
  **原游戏文件夹分毫不动** —— 个人数据是不打进压缩包，不是从磁盘上删掉，你的存档一个字节都不会少。
  规则按「名字 + 所在位置」双重限定：`*.dat` 在存档目录里是存档，在游戏根目录下就是
  BGI 引擎的游戏本体，一刀切会压出一个跑不起来的包，所以只按位置判定、并且都由你确认
- **卸载仪式** — 三步确认：确认对象 → **手抄花名** → 长按 2.5 秒。
  第二步会随机抽一种花（十八种，附拉丁学名与花语），要你把它的英文名抄一遍 ——
  要删哪个上一步已经确认过，这一步只为让手慢下来。
  第三步按住不放，磁贴会像镜子一样裂开、碎片错位掉落，同时落下的是你抄的那种花的花瓣；
  中途松手即中止，碎片合回去，一切照旧。
  执行顺序：游戏自带卸载程序 → Geek Uninstaller → 移入回收站

### 外观

- **主题** — 樱花（默认）/ 夜樱（深色）/ 初音 / 抹茶 / 海盐 / 薰衣草。
  全部由 CSS 自定义属性驱动，换主题时连生成的占位磁贴和飘落花瓣都会跟着变色
- **窗口不在前面的时候，花瓣降到 8 帧** — 启动器一辈子大半时间待在游戏后面。
  浏览器只在窗口**被隐藏**（最小化、切到别的虚拟桌面）时才自己降帧，仅仅是失去焦点、
  或者被全屏游戏整个盖住，画布照样每秒画六十遍给没人看的东西。花瓣的运动按**实际流逝的
  时间**积分而不是按帧数，所以降帧不改变它们下落的快慢，只是画得稀疏一些；
  切回来立刻恢复
- **中英双语** —— 界面、启动错误、诊断结论、写进游戏文件夹的说明文件，全都跟着切；
  说明文件两种语言都读得回来，所以换了语言之后旧文件不会失效
- **没有系统标题栏** — Windows 那条白色的关闭条不认主题，不管窗口是樱花还是夜樱，它永远是
  白的。所以整个窗口去了边框，**顶栏自己就是标题栏**：拖它就是拖窗口，双击最大化，
  贴边吸附照旧，右端三个花色圆点是最小化 / 最大化 / 关闭，悬停才显出图标，关闭那个悬停变
  深色。代价是 Win11 悬停最大化按钮弹出的分屏布局菜单没有了 —— 那个菜单只有系统按钮能召出来
- **启动动画** — Electron 从双击到画出书架要一两秒，那段时间 Windows 什么都不显示，
  于是人会再点一次。现在会立刻弹出一个樱花小窗，等书架真正画好才交接

## 数据存放

全部用户数据都在 `%APPDATA%\sakura-launcher\`：

```
db.json              游戏、分组、设置、已移除路径
cache/icons/         从可执行文件提取的图标
cache/breakdown/     目录体积构成缓存
covers/              用户自己设置的封面
magpie/              Magpie 及其配置（第一次开启超分放大时复制过来，约 30 MB）
lossless/            用 Lossless Scaling 时，它的配置文件在被本程序改动之前的备份
```

存档备份不放在这里，默认写到「文档\Sakura Launcher Saves」，设置里可改 ——
备份跟着这个目录一起被删掉就不叫备份了。

删掉这个目录即回到初始状态。项目目录里不写任何用户数据。
每个游戏文件夹里另有一份 `sakura-launcher.md`，是同一批数据可携带、可手改的副本。

## 依赖的外部程序（都是可选的）

**Magpie 是唯一随安装包一起分发的**，其余几个都只是「装了就能用，没装也不影响」。

- **Magpie**（GPL-3.0，v0.12.1）— 超分放大用的独立程序，随安装包分发，**默认关闭**。
  第一次开启时复制到 `%APPDATA%\sakura-launcher\magpie\` 并在那里写自己的配置 ——
  它需要一个可写的目录，而这样也保证了你自己装的那一份 Magpie 从不被读取或改写。
  分发的是上游原始压缩包，未经修改，构建时校验 SHA-256。
  许可证全文与对应源码的取得方式见 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。
  注意它是单实例的：你自己的 Magpie 开着时，本程序不会再起一个，而是提示你先退出它
- **Lossless Scaling**（Steam 上的付费闭源软件）— 超分放大的另一个可选后端，**不随包分发**，
  需要你自己购买并安装。本程序只做两件事：从 Steam 的库记录里找到它（找不着可以手动指定），
  以及往它自己的配置里加几条以「Sakura · 」开头的游戏配置 —— 内容整份复制自你选定的那一条，
  写之前先备份，你自己建的配置从不改动，换掉这个后端时删干净
- **7-Zip** — 解压「待安装」的压缩包条目，以及分享时打包。未安装则这两项不可用，
  其余功能不受影响
- **Geek Uninstaller** — 卸载链的第二级。未安装则没有自带卸载程序的游戏直接走回收站，
  也可在设置里手动指定路径
- **IDM / aria2c** — 下载功能可选的后端。都没有就交给系统默认程序
- **DLsite / VNDB / Bangumi** — 题材标签的来源，**默认不启用**，都不需要账号或密钥。
  DLsite 按作品编号精确查并给出中文分类；VNDB 按标题搜（含中文标题）并提供标签；
  Bangumi 只用来把中文名换成日文原名 —— 它的条目详情接口对成人向作品要登录，
  所以标签不从那里来。三个站分开限速：VNDB 每 2 秒（照它公布的每 5 分钟 200 次算），
  另两个每 1 秒。三十来个游戏的库实测约 100 秒

## 从源码运行

```bash
npm install
npm run dev
```

打包（产物都在 `release/`）：

```bash
npm run dist:all           # 安装版 + 便携版，一次出两个
npm run dist:setup         # 只出安装版
npm run dist:portable      # 只出便携版
```

三个 `dist:*` 都会先跑 `npm run magpie:fetch`：**从 GitHub 下载一次 Magpie 的发布包并校验
SHA-256**，解压到 `resources/magpie/`（不进版本控制）。这是整个项目里唯一会联网的构建步骤，
和「程序运行时不联网」是两回事 —— 装好之后 Magpie 的自动更新检查被强制关掉。
没跑过它也能 `npm run dev`，只是超分放大会显示「尚未复制」。

不启动整个应用就能验证的部分：

```bash
npm run sidecar-test                              # 说明文件的读写与冲突合并
npm run exe-pick-test                             # 可执行文件分类与排序
npm run downloader-test                           # 下载器探测与完成判定
npm run diagnose-test                             # 启动诊断：运行库映射、乱码识别、引擎判定；
                                                  # PE 解析拿真实系统二进制验，仓库里不放样本
npm run tag-test                                  # 题材标签：哪些标题算对上、哪些目录站标签该丢；
                                                  # 以及简介该不该收：不是中文的、名字对不上的一律不要。
                                                  # 不联网，响应形状用真实样本钉住
npm run magpie-test                               # 超分放大：三态开关（总开关关掉就是真的关掉）、
                                                  # 配置合并的幂等性、以及缩放模式必须按名字查索引
npm run lossless-test                             # Lossless Scaling：改别人的配置文件 ——
                                                  # 游戏配置区以外必须逐字节不变、同样的库必须
                                                  # 产出同样的文件、只删自己加的那几条
npm run cover-test                                # 封面：哪张图能用、哪张算 R18、伪装成图片的
                                                  # 错误页必须被拒，用户自设的封面不许被批量覆盖
npm run translate-test                            # 翻译简介：怎么切块、两家服务的响应形状、
                                                  # 以及「要么整段要么不要」
npm run save-test                                 # 存档定位：哪些文件夹算这个游戏的、哪些只是名字
                                                  # 撞车，以及随下载附带的存档必须被认出来
npm run share-test                                # 分享的排除规则（重点是不该命中的那些）
npm run share-e2e                                 # 真的调 7-Zip 压一遍，断言原文件夹分毫未动
node scripts/scan-test.mts "<游戏库文件夹>"        # 打印识别到的游戏、压缩包、分组候选

npm run diagnose-probe -- "<一个游戏文件夹>"       # 只读地打印诊断能看到的一切
```

后三个要求把目录作为参数传入 —— 仓库里不含任何预置路径。

## 技术栈

Electron + React + TypeScript，构建用 electron-vite。
PE 图标解析用 [resedit](https://github.com/jet2jet/resedit-js)（纯 JS，无需原生编译）；
导入表解析是自己写的，因为 resedit 会拒收一些合法但少见的布局 —— 偏偏就是那些引擎的可执行文件。
目录遍历与体积统计跑在 worker 线程里，不阻塞界面。
